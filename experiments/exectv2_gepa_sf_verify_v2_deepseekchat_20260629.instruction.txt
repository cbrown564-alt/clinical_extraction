=== generate ===
You are given a clinical letter from an epilepsy consultation. Your task is to extract every distinct seizure-frequency statement and output them as a JSON object with a single key "events" containing a list of event objects. Each event corresponds to one (seizure type × distinct frequency statement). If a seizure type appears in multiple distinct statements (e.g., a current numeric rate and a separately reported change), list it more than once.

**Output schema (strict JSON, no markdown):**
```json
{"events": [
  {
    "applies_to": "<seizure type as written in the letter, or 'seizures' if generic>",
    "change_direction": "increased | decreased | null (only when kind = 'changed')",
    "evidence": "<exact verbatim substring from the letter>",
    "kind": "frequency_rate | cluster_frequency | seizure_free | changed | unknown"
  }
]}
```

**Definitions of `kind`:**

- **`frequency_rate`**: An explicit numeric rate with a time period (e.g., “2 per year”, “weekly”, “around 2 per year”, “occasional” when it clearly indicates a frequency). **Also** a single recent seizure event (e.g., “had another seizure”, “he had a seizure”) – this implies current active seizures and is treated as a rate. **Do NOT** include counts of multiple events without a time frame (e.g., “4 more attacks”, “three or four further episodes”) – those are not a rate.
- **`cluster_frequency`**: A statement about the cadence of seizure clusters (e.g., “clusters every two weeks”). Not used in examples but available for completeness.
- **`seizure_free`**: Explicit statement that seizures have stopped, none, or X seizure‑free (e.g., “no seizures”, “seizure‑free for three years”, “her last event was more than five years ago”, “has not had any further episodes”). Do **NOT** interpret vague control statements like “epilepsy seems to be under control” as seizure‑free.
- **`changed`**: An **explicit qualitative** directional change using words such as “increase”, “decrease”, “improvement”, “worsening”, “more frequent”, “less frequent”, “better”, “worse”. Vague statements like “helped”, “continues to get”, “may have helped” are **not** enough. Only emit `changed` when the direction is clearly stated.
- **`unknown`**: A mention of seizures without a usable frequency (e.g., “she still gets myoclonic jerks” without any rate, or a single past event like “her seizure was 2 months ago” that does not indicate current activity). Use this as a fallback when none of the above apply.

**Rules for `change_direction`:**  
Only include this field when `kind = "changed"`. Then set it to `"increased"` or `"decreased"` based on the explicit wording. For all other kinds, set to `null`.

**Important constraints (derived from feedback):**

1. **Only extract statements about seizure types that are part of the patient’s known diagnosis or explicitly described as the patient’s seizures.** Do not extract statements about vague events (e.g., “transient loss of consciousness” in a letter where epilepsy is only suspected) unless the letter clearly labels them as seizures.
2. **Do not treat past frequency rates** (e.g., “used to happen weekly”) as current `frequency_rate`. They do not describe the present status. If they are the only mention, omit them or classify as `unknown` if they still indicate a past pattern? In practice, ignore them unless they are the current state.
3. **A single seizure event** (e.g., “had another seizure”, “he had a seizure on 2nd November”) **is** a `frequency_rate` because it indicates current active seizures. But a count of multiple events without a time period (e.g., “4 more attacks”) is **not** a valid rate and should be omitted.
4. **A statement that seizures have stopped** (even if followed by a later single event) should be captured as `seizure_free` for that time period. The later single event then becomes a separate `frequency_rate`.
5. **Be exhaustive (recall‑oriented):** List every distinct statement. If you are unsure, include it – the verify stage will remove unsupported ones. However, avoid obvious over‑calls like marking vague mentions as `changed` or `frequency_rate` when they do not meet the definitions.
6. **Evidence must be an exact substring** copied from the letter, preserving original spelling and punctuation.

**Examples of correct vs. incorrect (from feedback):**

- ✅ “around 2 secondary generalised seizures per year” → `kind: frequency_rate`
- ✅ “seven years without any tonic clonic” → `kind: seizure_free`
- ✅ “had another seizure whilst he was asleep on the 2nd November” → `kind: frequency_rate` (single event)
- ✅ “She thinks that this may have helped her seizures” → **NOT** `changed` (vague). Omit or mark `unknown`? Better to omit if no explicit direction.
- ✅ “The epilepsy seems to be under control” → **NOT** `seizure_free` (vague). Omit.
- ✅ “four more attacks” → **NOT** `frequency_rate` (no time frame). Omit.
- ✅ “used to happen weekly” → **NOT** `frequency_rate` (past). Omit unless the letter indicates it is still current.
- ✅ “continues to get myoclonic jerks” → **NOT** `changed` (no explicit direction). Use `unknown` only if it is the only mention; otherwise omit? In example 3 gold considered it `changed`? That was an outlier; follow the rule: only explicit direction.

Apply these rules consistently. Return exactly one JSON object with an `events` list. No markdown, no extra text.

=== verify ===
You are a recall-additive verifier. You read the clinical letter and a DRAFT list of seizure-frequency events, and you output the COMPLETED, corrected list. The draft usually MISSES facts: add every seizure-frequency statement the draft omitted — especially seizures that have STOPPED (kind=seizure_free) and additional seizure types the draft consolidated away. Keep every well-supported draft event; remove only events the letter does not support; do NOT merely prune. Be PRECISE about kind=changed: emit it ONLY when the letter contains an explicit statement that the frequency increased, decreased, improved, or worsened (a directional comparison in words). Do NOT emit changed merely because a numeric rate is present, because a single dated event occurred, or for vague/non-directional statements ('fluctuates', 'variable', 'ongoing'). When the letter gives BOTH a current rate AND a separate explicit change statement for the same seizure type, emit BOTH a frequency_rate event and a changed event. Return exactly one JSON object matching output_schema with the full 'events' list, no markdown.
