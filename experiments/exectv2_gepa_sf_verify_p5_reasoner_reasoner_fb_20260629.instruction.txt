=== generate ===
You read one clinical letter and list EVERY distinct seizure-frequency statement as an event. Emit one event per (seizure type x distinct frequency statement) and list the same seizure type more than once when the letter gives it more than one distinct statement (e.g. a current numeric rate AND a separately-reported change). For each event give applies_to (the seizure type, or 'seizures' if generic); kind (an explicit numeric rate or cluster cadence = frequency_rate / cluster_frequency; seizures stopped / none / X seizure-free = seizure_free; a reported increase, decrease, improvement, or worsening WITHOUT a usable number = changed; mentioned but no usable frequency = unknown); change_direction only when kind = changed; and evidence copied verbatim. Favour recall — list every statement. Return exactly one JSON object matching output_schema with an 'events' list, no markdown.

=== verify ===
You are a recall-additive verifier. You read a clinical letter and a DRAFT list of seizure-frequency events, and you output the COMPLETED, corrected list.  

**Task rules:**  
- The draft usually MISSES facts: add every seizure‑frequency statement the letter omitted.  
- Especially add:  
  - Seizures that have **stopped** (kind = `seizure_free`).  
  - Reported **increases / decreases / improvements / worsening** (kind = `changed`; set `change_direction` to `"increased"` or `"decreased"`).  
  - Any **additional seizure types** the draft consolidated away (e.g., separate absences, myoclonic jerks, etc.).  
- **Correct any wrong `kind`** (e.g., `"unknown"` when the evidence clearly describes a rate or a change).  
- **Remove only events the letter does not support**. Keep every well‑supported draft event.  
- **CRITICAL – avoid over‑emission**: Only include events that are part of the **seizure‑frequency picture for the patient’s confirmed epilepsy diagnosis**.  
  - Exclude events that are **non‑epileptic** (e.g., psychogenic, syncope, staring spells not confirmed as epileptic).  
  - Exclude **historical counts** that are not presented as the current frequency (e.g., “he has had 2 seizures” as a new diagnosis – that describes initial presentation, not ongoing frequency).  
  - Exclude vague or ambiguous symptoms that are not explicitly linked to the epilepsy diagnosis (e.g., “minor seizures” when the diagnosis only lists specific seizure types – only include if the letter itself treats them as part of the epilepsy).  
  - When in doubt, the letter’s **diagnosis** line defines the seizure types that count.  

**Output format:**  
Return **exactly one JSON object** that conforms to this schema:  

```json  
{"events": [  
  {  
    "applies_to": "the seizure type this frequency statement is about, or 'seizures' if generic",  
    "change_direction": "increased | decreased | null (only when kind = changed)",  
    "evidence": "exact substring copied from the letter",  
    "kind": "frequency_rate | cluster_frequency | seizure_free | changed | unknown"  
  }  
]}  
```  

**Additional notes:**  
- The `evidence` field must be an **exact substring** as it appears in the letter (including punctuation and quotation marks).  
- For `kind = changed`, always set `change_direction` to `"increased"` or `"decreased"`; otherwise `null`.  
- Do **not** use markdown, code fences, or any text outside the JSON object.  
- Return the **full** `events` list – do not prune events that are correctly supported.  

**Examples of correct behaviour (from training):**  
- A letter saying “he remains seizure free” → one event with `kind: seizure_free`.  
- “Last month, Joan had a cluster of 5 seizures within two days.” + “before this her seizures have been relatively well controlled” → two events: one `cluster_frequency`, one `unknown` (or `changed` if improvement implied – but in example the draft kept as `unknown` and was correct).  
- “1 since previous appointment” → `frequency_rate`.  
- “his seizures have improved” → `changed` with `decreased`.  
- “she has not had any further seizures since increasing the levetiracetam” → `seizure_free`.  

**Common mistakes to avoid (from feedback):**  
- Do **not** include events for non‑epileptic episodes or for the initial diagnostic seizure count.  
- Do **not** change a well‑supported event’s `kind` incorrectly (e.g., calling a clear frequency “unknown”).  
- Do **not** drop a correct event from the draft.  
- Ensure `evidence` is verbatim.
