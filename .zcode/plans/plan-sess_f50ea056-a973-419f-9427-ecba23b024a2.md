## Goal
Replace the standalone 3.2 MB `exectv2_sf_inspection_dev140_20260708.html` with a first-class frontend route (`/exectv2-sf-inspection`, top-level nav tab) that renders the same Layer A / Layer B / lineage depth through the existing design system. **All computation and the faithfulness gate stay in Python** — only the presentation moves to React.

## Architectural seam (the invariant)
The renderer script's value is Python-only: the 11-component key builders, `score_frequency_state`, and the gate that ABORTS unless aggregate F1 reproduces `0.9338 / 0.8602 / 0.9244` within 1e-4. None of that can move to the browser.

- **Python computes** a fully-resolved, faithfulness-checked payload → serves it as one process-cached JSON blob.
- **Frontend renders** that blob via a thin adapter + the `GoldNoisePanel` inspection pattern.
- The gate now guards the *JSON artifact* the backend serves, not an HTML file — strictly stronger than today.

## What this preserves vs. gains
- **Preserves:** every one of the 11 components, per-mention TP/FP/FN attribution, Layer A attribute canonicalization, lineage/override panel, the faithfulness gate (now test-backed).
- **Gains:** searchable/filterable letter list, master-detail drill-down, consistent typography/tone, lives where the product lives, gate covers the live-served payload not a static file.
- **The one UX shift:** one letter at a time in the right rail instead of all 140 collapsibles in one page — mitigated by the dense error-badged master list + "errors only" filter.
