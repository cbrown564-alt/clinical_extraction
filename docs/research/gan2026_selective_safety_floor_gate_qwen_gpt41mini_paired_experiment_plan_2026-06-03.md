# Gan 2026 Selective Safety-Floor Gate Paired Model Experiment Plan

This plan tests how well `selective_safety_floor_gate_replay.py` transfers when
its source artifacts are generated by local Qwen models rather than
`openai/gpt-4.1-mini`.

## Core Design

The selective gate replay is a no-call analysis layer. Therefore the paired
experiment must generate matched upstream artifacts first, then replay the same
frozen gate over each artifact.

Paired unit:

- Same pipeline: `hybrid_parallel_state_candidate_reasoner`
- Same split/order: validation prefix rows from `gan2026_split_v1`
- Same limits: `1`, `25`, `50`, `250`, optional `750`
- Same prompt/program: `gan2026_hybrid_parallel_state_candidate_reasoner_v0`
- Same decoding: temperature `0.0`, max tokens `1800`
- Same cache stance by default: DSPy cache disabled for both live model arms
- Same gate manifest:
  `experiments/gan2026_selective_safety_floor_gate_v0_validation_cycle_manifest_2026-06-03.json`
- Different model only:
  `openai/gpt-4.1-mini` versus local `ollama_chat/qwen3.6:35b`

Primary local Qwen model is `ollama_chat/qwen3.6:35b` through native Ollama chat
at `http://localhost:11434` with thinking disabled by the shared LM builder.
Any smaller Qwen model can be added as a secondary arm, but should be reported
as a capacity-constrained sensitivity analysis rather than the main comparison.

## Experiment Ladder

1. Endpoint smoke, validation1:
   confirm local Qwen returns parseable structured outputs and the gate replay
   can consume the resulting artifact.

2. Format robustness, validation25:
   compare parse failures, schema repairs, evidence exactness, source-id
   validity, fallback count, and selective-gate changed rows against the GPT
   pair.

3. Decision stability, validation50:
   check whether Qwen and GPT fire the same gate families on the same row
   prefix, and whether Qwen introduces deterministic-correct regressions.

4. Development readout, validation250:
   primary local-vs-hosted comparison before any full validation run.

5. Optional validation750:
   run only after the validation250 pair is clean. This requires an explicit
   escalation reason because the shared CLI treats validation runs above 250 as
   non-routine.

## Metrics

Report all metrics for the `selective_safety_floor_gate_v0` layer and, where
useful, the component layers:

- Purist correct and Pragmatic correct
- Changed rows versus `baseline_safety_floor_v2`
- Wrong-to-correct and correct-to-wrong transitions
- Deterministic-correct regressions
- Changed-label precision
- Changed rows with exact evidence
- Changed rows with valid source ids
- Fallback or abstention count
- Hidden-family summaries
- Wall-clock throughput and seconds per row
- Schema repair and parse-failure counts from the upstream model report

The main paired comparison is not just aggregate accuracy. It is whether Qwen
preserves the gate's safety invariants while producing comparable sidecar
rescues on the same rows.

## Stop Rules

Promote Qwen to a serious local candidate only if validation250 has:

- `0` deterministic-correct regressions
- no unexplained correct-to-wrong transitions
- every changed row has exact evidence and valid source ids
- changed-label precision within an acceptable band of the GPT pair
- no material increase in schema/parse failures that changes gate eligibility

Revise before scaling if Qwen mostly abstains, produces malformed sidecar
selections, or changes rows through weaker evidence provenance.

Reject the Qwen arm for this gate if it creates deterministic-correct
regressions, changed rows without valid evidence/source ids, or a materially
worse safety profile than GPT on validation250.

## Runner

Use the paired runner from the repo root in PowerShell:

```powershell
.\experiments\run_selective_safety_floor_gate_paired_models_2026_06_03.ps1
```

For a no-call dry run of prompt construction and replay plumbing:

```powershell
.\experiments\run_selective_safety_floor_gate_paired_models_2026_06_03.ps1 -PromptOnly -Limits @(1)
```

This dry run is not a model comparison. It records `not_run` model outputs and
exercises deterministic fallback/replay plumbing only.

For the optional full validation pair:

```powershell
.\experiments\run_selective_safety_floor_gate_paired_models_2026_06_03.ps1 -Limits @(250) -IncludeValidation750
```

To add another local Qwen arm:

```powershell
.\experiments\run_selective_safety_floor_gate_paired_models_2026_06_03.ps1 `
  -QwenModels @("ollama_chat/qwen3.6:35b", "ollama_chat/qwen3.6:27b")
```

The runner writes one upstream JSONL/report and one selective-gate replay
JSONL/JSON/report per model and limit, plus a compact paired summary JSON:

`experiments/gan2026_selective_safety_floor_gate_v0_paired_model_results_live_2026-06-03.json`

Prompt-only dry runs use `prompt_only` in artifact names and write:

`experiments/gan2026_selective_safety_floor_gate_v0_paired_model_results_prompt_only_2026-06-03.json`

By default the runner uses `.venv\Scripts\python.exe` when that file exists,
falling back to `python`. Use `-PythonExe` to point at another environment.
Use `-EnableDspyCacheForGpt` only when intentionally comparing Qwen to a cached
GPT reference artifact.
