What we built

What this project does

Doctors write clinic letters in free text. We build software that turns those letters into structured fields a computer can use — seizure counts, diagnoses, drug names, test results. We do not ask a model to jump straight to the final answer; we split the work so each step can be inspected.

Track 1 — one label per letter

On synthetic letters, we extract seizure frequency only. The main lesson: extract facts first, then let rules choose the clinically current answer. Some hard cases still fail even when the model is confident — we call that limit The Wall (see Limits tab).

Track 2 — many fields per letter

On real de-identified letters, we extract a full epilepsy profile. The main lesson: a strict benchmark score can look much worse than clinical judgment because gold labels list facts differently than a clinician would consolidate them — we call that the gold-quality ceiling (see Limits tab).

Find facts (language model)

The model returns a list of mentions — e.g. a rate, a seizure-free statement, or unknown — each tied to a quote and marked historical or current. It does not output the final scored label.

Pick the current fact (rules)

When the letter mentions both an old seizure rate and current seizure freedom, rules prefer the current clinically relevant rate (unless policy says otherwise).

Track 2 · Pipeline

Extractors propose, rules reconcile

Several extractors each read the letter for their topic. Rules collect all proposals, reconcile conflicts, and produce both a clinician-facing summary score and a stricter benchmark view for debugging.

Extractors (language model) Collection, reconciliation, dictionaries Primary composite score

Extractors (language model)

Separate passes (or hybrid steps) propose findings — e.g. a diagnosis mention, a seizure-free statement, a drug dose — each with supporting text from the letter.

Project term: producers / CandidateProducer

Collect findings (rules)

All proposals land in one per-letter store so we can turn components on/off and measure what each layer contributes.

Project term: ClinicalFindingStore

Reconcile by topic (rules)

Topic-specific logic merges duplicates, handles negation, and picks clinically coherent states — e.g. seizure-free vs active rate for the seizure-frequency field.

Project term: entity lenses

Build views (rules)

We can project the same findings into a clinician-facing summary (used for the 86% headline) or a strict legacy benchmark (useful for debugging format gaps).

Project term: clinical_headline vs benchmark/CUI surfaces

Provenance (rules)

Every emitted finding records which extractor and rule step produced it — needed for component ablation claims.

Important limits

Why scores stop improving

Both tracks hit ceilings — but for different reasons. One is a model that is confidently wrong; the other is a scoreboard that counts answers differently than a clinician would. Do not mix up the two stories.

Track 1 · seizure frequency

Confident mistakes on ambiguous letters

On the hardest remaining letters, the model picks a specific seizure rate even when a clinician would say “unknown.” Nothing in the model’s own confidence scores reliably flags these cases ahead of time.

Best seen (~84%)
84%
Our pipeline (81%)
81%

We call this limit The Wall — a research prior (~84%), not a target to prompt-tune toward.

Example pattern
The letter hints at past seizure burden but never states a current countable rate. The model outputs a frequency band anyway; the gold label is “unknown.” Uncertainty metrics stay flat — the mistake looks confident.
Project vocabulary & metrics
  • Binding residuals: rows where only the hidden gold label tells you the model should abstain
  • P2.1: semantic entropy flat on residuals → over-reading is confident
  • 11 irreducible validation rows; external risk AUROC 0.781
Track 2 · full profile

Scoreboard vs clinical judgment

The strict benchmark expects facts listed the way annotators encoded them. The model often merges equivalent statements — clinically fine, but marked wrong by the strict matcher.

Clinically OK
89%
Strict benchmark
62%

We call this the gold-quality ceiling — most apparent “errors” are representation mismatch, not missing clinical concepts.

Example pattern — diagnosis
Gold lists “focal epilepsy” and “temporal lobe epilepsy” as two rows; the model outputs one merged diagnosis. A clinician would accept the merge; the strict benchmark does not. ~85% of diagnosis disagreements look like this.
Project vocabulary & caveats
  • Rescoring under state_profile can raise seizure-frequency scores without changing model output
  • Diagnosis adjusted F1 0.95 vs strict benchmark 0.66
  • Adjudication was done by the same team — note in methods
